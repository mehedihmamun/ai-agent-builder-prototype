For you to decide

1. Disabled buttons: tint or fade? · Decided: tints, applied

Your Button guidelines (V2.0) say a lighter tint per variant, e.g. Primary blue-40, Secondary offwhite-40 with gray-40 text, Ghost gray-40 text. Your design system's bundle code still uses a 50% fade. The prototype follows the code, so every disabled button fades.

Option: override the disabled state in the prototype to match the guidelines, or update the design system bundle first so every product gets it.

2. Disabled send button · Now blue-40, per the guidelines

It replaces the Blue 60 from the Figma review, so it matches every other disabled Primary button.

3. Canvas "+" buttons should use the add variant

The guidelines define add: 28px, round, white, turning primary on hover. The prototype already asks for add, but the bundle doesn't have that variant yet, so the button falls back to a small 20–24px square with a gray border.

4. Round icon buttons

The chat composer (36px) and canvas toolbar (32px) buttons are round. The spec's icon buttons have 8–10px radius. Round may be the intended look for chat and canvas, but it isn't in the spec.

5. Black "Add a step" button

A 44px black round button sits on the canvas. There's no matching variant, and the spec's add is white.

6. Label casing · Decided: sentence case, applied

Button labels use sentence case: only the first letter is capital ("Create agent", "Learn more", "Explore template", "Browse all templates"). Names keep their capitals (WhatsApp, Shopify, AI).
